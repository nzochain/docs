<Warning>
  **Legado.** Continua operacional para a app B2C e integrações antigas, mas **não** é o contrato recomendado para produtos novos.
  Preferir **[POST /api/v1/wallets/risk](/api/v1)** com header `X-API-Key`.
</Warning>

## Endpoint

```
POST https://api.nzochain.com/api/risk/scan
```

Auth: sessão B2C **ou** chave B2B (`X-API-Key`) via o guard partilhado. Developers novos devem usar a **API v1**.

## Request body

Campos confirmados no DTO `ScanRiskDto` (`nzochain-backend`):

| Campo | Tipo | Obrigatório | Notas |
|---|---|---|---|
| `wallet` | string | sim | Morada EVM `0x…` |
| `network` | string | não | `ethereum` \| `bnb` \| `polygon` \| `arbitrum` (default `ethereum`) |
| `forceRefresh` | boolean | não | Ignora caches |
| `includeBlocked` | boolean | não | Inclui blacklist pessoal |
| `requesterWallet` | string | não | Contexto opcional |

**Solana não é suportada.** Não existe campo `chain` nem `include_details` neste DTO.

### Exemplo

```json
{
  "wallet": "0x742d35Cc6634C0532925a3b8D4C9B5e55d7b1234",
  "network": "ethereum"
}
```

## Resposta (camada legado)

A resposta legado inclui tipicamente `wallet`, `network`, `riskScore`, `warnings`, `status` e `transactionsAnalyzed` (mais `meta` / sinais opcionais). O envelope HTTP pode ser envolvido pelo interceptor (`success` / `data`).

Para o contrato estável B2B (`riskLevel`, `decision`, `reasons`), usa a [API v1](/api/v1).

## cURL (legado)

```bash
curl -X POST "https://api.nzochain.com/api/risk/scan" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: YOUR_API_KEY" \
  -d '{"wallet":"0x742d35Cc6634C0532925a3b8D4C9B5e55d7b1234","network":"ethereum"}'
```
